## 2. 背景与目标

订单是交易链路的唯一入口，重复提交、重复点击与网络重试都会造成重复建单，进而产生重复支付与重复权益。本条目确立下单的服务端权威边界：用户身份只来自网关注入的 `X-User-Id`，金额只由服务端按课程审核确认价与优惠券计算，幂等由「用户 + 幂等键」唯一约束兜底，且幂等键绑定请求体摘要——同一键只能代表同一次购买意图。完成后，同一用户的同一次购买意图无论重放多少次，都只对应一笔订单；换课程或换券的重放被拒绝而不是返回旧单。

2026-11-13 负责人决定支持购物车多门课程合并为一笔订单：`courseId` 单课程路径的契约与语义保持不变，新增 `courseIds` 走合并路径，金额仍由服务端按分汇总。

## 3. 范围

### 3.1 包含

- `POST /api/v1/orders` 创建订单：`courseId` 为单课程下单，`courseIds` 为多门课程合并为一笔订单，两者互斥。
- `Idempotency-Key` 头的校验、并发占位与成功结果重放，以及 `uk_idempotency(user_id, idempotency_key)` 唯一约束兜底。
- 下单前的课程可售校验、已购校验、优惠券核销（券规则本身见 SPEC-TRADE-003）。
- 由服务端计算 `total_amount`、`discount_amount`、`pay_amount`；合并订单每门课程落一条 `trade_order_item`，金额按分汇总。

### 3.2 范围外

- 应付为 0 时的即时完成与权益发放，见 SPEC-TRADE-002。
- 支付渠道固定与小程序下单拒绝，见 SPEC-TRADE-004。
- 权益发放的最终一致与重复投递吸收，见 SPEC-LEARN-001。
- 合并订单的优惠券抵扣：整单券按行摊销本期不做，合并请求携带 `couponId` 直接返回 `40001`，见 AC-12。

> 原「购物车结算与合并下单，本期不做」已由负责人 2026-11-13 决定修订为纳入本期，验收见 AC-8 至 AC-12。

## 4. 用户场景

| 编号 | 类型 | 场景 | 期望结果 |
|---|---|---|---|
| S-1 | 正常 | 学员在 Web 课程详情页点击购买，前端按购买意图生成一个幂等键放入 `Idempotency-Key` 头并提交一次 | 返回订单号，状态为待支付，`payAmount` 等于课程最终价减优惠 |
| S-2 | 正常 | 前端因超时重试，使用同一幂等键再次提交 | 返回与首次完全相同的订单号与金额，订单表仍只有一条记录 |
| S-3 | 边界 | 两个请求并发携带同一幂等键提交 | 首个请求 5 秒内完成时两个响应指向同一订单号；超过 5 秒未完成时另一请求返回 `40902`，用同一键重试仍得到首单；数据库只落一条 `trade_order` |
| S-4 | 异常 | 学员已持有该课程有效权益再次下单 | 返回 `61002`，不创建订单 |
| S-5 | 异常 | 请求体伪造 `userId` 或 `price` 字段 | 用户以 `X-User-Id` 为准，金额以服务端计算为准，伪造字段不生效 |
| S-6 | 异常 | 前端复用上一次的幂等键但更换了课程或优惠券 | 返回 `40901`，不创建新订单，也不返回旧订单 |
| S-7 | 正常 | 学员在购物车勾选两门及以上课程一起结算，提交 `courseIds` | 只创建一笔订单，每门课程一行，`payAmount` 由服务端按分汇总 |
| S-8 | 异常 | 前端以相同课程集合但不同顺序重复提交，或课程集合、金额发生变化 | 顺序不同返回同一订单号；集合或金额变化返回 `40901`，不创建第二笔订单 |

## 5. 验收标准

- AC-1：同一用户使用同一 `idempotencyKey` 重复或并发提交下单请求时，数据库只产生一条 `trade_order`，且所有成功响应返回同一个 `orderNo`。
- AC-2：下单前若该用户在 `user_entitlement` 存在 `user_id + course_id` 的有效权益，接口返回 `61002` 并且不写入任何订单记录。
- AC-3：课程当前状态不为已上架（`status != 2`）时下单返回 `62003`，不创建订单，也不核销优惠券。
- AC-4：下单请求体不接受价格字段，客户端传入 `price`、`payAmount` 或 `totalAmount` 任一时，订单金额仍等于服务端按课程最终价与优惠券计算的结果。
- AC-5：同一用户使用同一幂等键但请求体中的 `courseId` 或 `couponId` 与首单不一致时，接口返回 `40901`，不创建新订单、不发放权益，也不以最后一次请求覆盖原订单。
- AC-6：下单必须携带 `Idempotency-Key`（过渡期兼容 body `idempotencyKey`），缺失、超过 64 字符或含非法字符时返回 `40001`，且不落单、不核销优惠券。
- AC-7：同一用户同一幂等键并发提交时只产生一条订单；首个请求 5 秒内完成时另一请求返回同一 `orderNo`，超过 5 秒返回 `40902` 且可用同一键重试，两种情况都不产生第二笔订单。
- AC-8：请求同时携带 `courseId` 与 `courseIds` 时返回 `40001`，不创建订单。
- AC-9：`courseIds` 去重后为空、含非正整数或超过 20 门时返回 `40001`，不创建订单。
- AC-10：多课程下单只创建一笔 `trade_order`，每门课程对应一条 `trade_order_item`，`payAmount` 等于服务端按分汇总的各行当前价之和。
- AC-11：合并订单的幂等摘要覆盖课程集合、优惠券与金额；同一课程集合以任意顺序重复提交返回同一 `orderNo`，课程集合、券或金额变化返回 `40901`。
- AC-12：合并订单携带 `couponId` 时返回 `40001`，不创建订单、不核销优惠券。

## 6. 边界与异常

| 编号 | 触发条件 | 系统表现 | 关联 AC |
|---|---|---|---|
| E-1 | 未携带或携带无效凭证 | 网关拦截并返回 `40101`，请求不进入 trade-service | AC-1 |
| E-2 | `courseId` 为空或非数字 | 返回 `40001`，不落单 | AC-3 |
| E-3 | `Idempotency-Key` 头与 body `idempotencyKey` 均缺失，或超过 64 字符、含非法字符，或两处取值不一致 | 返回 `40001`，不落单 | AC-6 |
| E-4 | 课程不存在或已逻辑删除 | 返回 `40401`，不落单 | AC-3 |
| E-5 | 优惠券不可用（不属于本人、已使用、过期、不满足门槛） | 返回 `62003`，整单回滚，订单与券状态均不变化 | AC-4 |
| E-6 | 同一幂等键第二次提交时课程已售罄或已下架 | 仍按幂等返回原订单，不因当前课程状态改变已建订单 | AC-1 |
| E-7 | 同一用户同一幂等键但 `courseId` 或 `couponId` 与首单不同 | 返回 `40901`，不创建新订单，也不返回首单 | AC-5 |
| E-8 | 同一幂等键的首次请求超过 5 秒仍未完成 | 返回 `40902`，不创建第二笔订单；客户端用同一键重试即得到首单或 `40902` | AC-7 |
| E-9 | 请求同时携带 `courseId` 与 `courseIds` | 返回 `40001`，不落单 | AC-8 |
| E-10 | `courseIds` 去重后为空、含非正整数或超过 20 门 | 返回 `40001`，不落单 | AC-9 |
| E-11 | 合并订单按分汇总后金额超出可存储范围 | 返回 `62003`，整单回滚，不落单 | AC-10 |
| E-12 | 合并订单携带 `couponId` | 返回 `40001`，不落单，也不核销优惠券 | AC-12 |
