## 2. 背景与目标

教师提交的课程必须经运营审核后才能被学员看到，且教师填写的价格只是拟定价格，最终售价由运营在审核时确认。若把「审核通过」和「上架」拆成两个动作，会出现审核通过但长期不可售的中间态，学员端价格也与运营确认价脱节。本条目把审核通过与定价、首次上架合并为同一个原子动作，并冻结驳回与审计要求。

## 3. 范围

### 3.1 包含

- `POST /api/v1/admin/courses/{courseId}/review` 的通过与驳回分支。
- 审核通过与最终价写入、课程状态 `1→2` 的同事务处理。
- 驳回原因校验与状态回退 `1→0`。
- 审核审计流水的必填字段。

### 3.2 范围外

- 教师建课、编辑与提交审核，见 SPEC-COURSE-001 与 SPEC-COURSE-003。
- 教师拟定价格的输入约束，见 SPEC-COURSE-011。
- 已上架课程的下架与再上架，见 SPEC-COURSE-005 与 SPEC-COURSE-006。
- 学员端课程详情与购买入口，见 SPEC-COURSE-007。

## 4. 用户场景

| 编号 | 类型 | 场景 | 期望结果 |
|---|---|---|---|
| S-1 | 正常 | 运营审核一门待审核课程，确认价格 199 元并点击通过 | 课程状态变为已上架，售价为 199 元，学员端立即可见 |
| S-2 | 正常 | 运营不修改价格直接通过，教师拟定价为 99 元 | 课程以 99 元上架 |
| S-3 | 正常 | 运营驳回并填写「封面不符合规范」 | 课程回到草稿，教师可见驳回意见并可修改后重新提交 |
| S-4 | 异常 | 运营驳回但未填写意见 | 返回 `40001`，课程保持待审核 |
| S-5 | 异常 | 两名运营同时对同一门待审核课程点击通过 | 只有一次审核生效，另一次因状态已不是待审核返回 `61005` |

## 5. 验收标准

- AC-1：审核通过时课程状态从 1 待审核直接变为 2 已上架，系统不存在「审核通过待上架」的中间状态，也不存在只改状态不写价格的通过路径。
- AC-2：审核通过后，学员端课程列表与详情立即返回该课程，展示价格与下单取价均为本次运营确认的 `priceFen`；未传 `priceFen` 时等于教师拟定价。
- AC-3：驳回时 `remark` 必填且长度为 1 至 300 字符，课程状态回到 0 草稿；`remark` 为空或超过 300 字符时返回 `40001` 且状态保持 1。
- AC-4：审核请求到达时课程状态不为 1 待审核，接口返回 `61005`，课程状态、价格与审计流水均不新增记录。
- AC-5：每次审核通过或驳回都写入一条审计记录，包含操作人 ID、操作时间、`fromStatus`、`toStatus` 与 `remark`，缺任一项视为实现不完整。

## 6. 边界与异常

| 编号 | 触发条件 | 系统表现 | 关联 AC |
|---|---|---|---|
| E-1 | 调用方角色不含 `ADMIN` 或 `OPS` | 返回 `40301`，不写审计 | AC-5 |
| E-2 | 课程不存在或已逻辑删除 | 返回 `40401` | AC-4 |
| E-3 | `priceFen` 为负数或超过两位小数 | 返回 `40001`，不改变课程状态 | AC-2 |
| E-4 | 课程缺少章节或有效课时 | 审核通过仍以课程内容校验结果为准，校验不通过返回 `40001` 并保持待审核 | AC-1 |
| E-5 | 通过事务提交后审计写入失败 | 审核与审计在同一事务内，任一失败整体回滚，不出现无审计的上架 | AC-5 |
| E-6 | 课程已被教师侧编辑 | 待审核课程对教师只读，编辑请求返回状态冲突，不会改变待审核内容 | AC-4 |
