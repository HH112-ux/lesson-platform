## 2. 背景与目标

真实收款开启后，平台账面（`payment_record` / `refund_request`）与渠道账面（支付宝账单）必须逐日核对，否则少收、多收与漏单都无法在资金层面被发现。本条目冻结对账的最小闭环：按渠道与账单日导入 T+1 账单，与本地记录逐笔比对，不一致时生成差异并告警，差异只能由运营人工核实后标记已处理；未处置差异阻断日结。对账**只读本地交易数据、只写对账聚合与日结批次**，不自动冲正、不发起退款、不改动用户资金与权益。

首版账单来源为 CSV 上传：运营从支付宝商户后台导出账单后导入。**支付宝账单接口尚未接入**（需商户号与账单权限），因此「自动拉账」不在本条已完成范围内。日结与结算接口按 2026-11-10 冻结口径实现（见 Q-2），只封账与汇总净额，不做任何资金动作。

## 3. 范围

### 3.1 包含

- 账单导入 `POST /api/v1/reconcile/import`：按 `channel`、`billDate`、`billType` 覆盖写入 `payment_reconcile`（唯一键 `uk_channel_date_type`）。
- 日查询 `GET /api/v1/reconcile/daily`：按渠道与账单日分页读取聚合。
- 重跑 `POST /api/v1/reconcile/{reconcileId}/recheck`：重新解析已存账单原文，与当前本地记录重算。
- 差异处置 `POST /api/v1/reconcile/{reconcileId}/handle`：人工标记已处理，写 `handled_by` / `handled_at`。
- 日结 `POST /api/v1/reconcile/settlements`：支付与退款两份账单均已导入且无未处置差异时，写入 `payment_settle_batch` 并锁定该账单日；重复日结返回同一批次。
- 作废 `POST /api/v1/reconcile/settlements/{batchId}/void`：批次置 `status=2`，写 `void_by` / `void_at`，账单日解锁后可重新日结。
- 日结查询 `GET /api/v1/reconcile/settlements/{batchId}` 与 `GET /api/v1/reconcile/settlements`：按渠道、账单日、状态分页读取批次，金额以分返回。
- 差异告警：ERROR 日志与 `reconcile_diff_total{channel}` 指标。
- 权限码 `admin:reconcile:view`、`admin:reconcile:recheck`、`admin:reconcile:handle`、`admin:reconcile:close`（仅 `ADMIN`）与角色门禁 `ADMIN` / `OPS`。

### 3.2 范围外

- 支付宝账单接口自动拉账与定时任务，依赖商户号与账单权限，见 7 未决问题 Q-1。
- 运营后台页面：日结与查询本期只有接口，页面未做，登记在 `docs/project-status.md` 4.2。
- 日结批次导出（CSV/Excel）不做。
- 手续费、分账、教师结算与任何资金动作：日结只封账与汇总净额。
- 差异的自动冲正、补单、追账与退款补偿：一律人工线下处置，系统不提供入口。
- 微信支付对账：渠道已下线，不新增对账任务。
- 资金分账与教师结算，见 `docs/engineering-plan.md` 1.3 首版不做项。

## 4. 用户场景

| 编号 | 类型 | 场景 | 期望结果 |
|---|---|---|---|
| S-1 | 正常 | 运营上传某账单日的支付宝支付账单，本地记录与账单完全一致 | 聚合 `status=1`，`diff_count=0`，不产生告警 |
| S-2 | 正常 | 运营重复上传同一渠道、同一账单日、同一账单类型的账单 | 覆盖同一行聚合，差异不翻倍，计数与金额以最后一次导入为准 |
| S-3 | 异常 | 账单笔数或金额与本地记录不一致 | 聚合 `status=2`，差异明细落 `diff_detail`，输出 ERROR 日志并累加差异指标 |
| S-4 | 正常 | 支付回调晚于账单导入到账，运营对同一账单日重跑对账 | 重算后差异消失，聚合回到 `status=1`，接口返回最新计数 |
| S-5 | 正常 | 运营核对差异后点击已处理 | 聚合 `status=3`，记录处理人与时间；订单、支付、退款与用户资金不变 |
| S-6 | 异常 | 重跑后差异仍然存在 | 重算结果先落库，接口返回 `50204`，该账单日仍被视为未完成对账 |

## 5. 验收标准

- AC-1：账单可凭渠道、账单日与账单类型导入；同一 `channel`、`bill_date`、`bill_type` 重复导入覆盖同一行，不产生重复差异，笔数与金额以最后一次导入为准。
- AC-2：账单与本地记录在笔数或金额上任一不一致时，服务端写入差异明细、把该账单日置为 `status=2`，并同时输出 ERROR 日志与 `reconcile_diff_total{channel}` 指标。
- AC-3：支付与退款两份账单都已导入（`status` 1–3）时方可日结，缺任一返回 `62019`；存在 `status=2` 的未处置差异时拒绝日结并返回 `50204`，不写批次。日结成功后写入该渠道账单日的批次并锁定账单日，重复日结返回同一批次，日结后的导入与重跑返回 `40901`；作废仅 `ADMIN` 可执行，作废后账单日解锁并可重新日结。
- AC-4：对账能力未达到「连续 3 个账单日 `diff_count=0`、且差异可在 24h 内定位到具体 `payment_record` / `refund_request`」前，生产环境不得开启真实收款。

## 6. 边界与异常

| 编号 | 触发条件 | 系统表现 | 关联 AC |
|---|---|---|---|
| E-1 | 渠道不是支付宝（`channel != 1`） | 返回 `40001`，不写聚合 | AC-1 |
| E-2 | 账单日缺失或账单类型不是 1 / 2 | 返回 `40001`，不写聚合 | AC-1 |
| E-3 | CSV 缺表头、列数不符、金额非正或超过两位小数 | 返回 `40001`，不写聚合 | AC-1 |
| E-4 | 账单为空但有本地记录，或本地为空但账单有记录 | 计为差异，`status=2`，`diff_amount` 为渠道减本地 | AC-2 |
| E-5 | 调用方缺少 `ADMIN` / `OPS` 角色或对应权限码 | 返回 `40301`，数据不变 | AC-1 |
| E-6 | 重跑或处置的聚合不存在 | 返回 `40401`，不做任何写入 | AC-1 |
| E-7 | 对非 `status=2` 的聚合执行处置 | 返回 `40901`，`handled_by` / `handled_at` 不被覆盖 | AC-3 |
| E-8 | 已标记处理（`status=3`）且重跑后差异未变化 | 保持 `status=3` 与处理人，不因重跑回退为待处理 | AC-3 |
| E-9 | 重跑后差异内容发生变化（新增或消除差异） | 按新结果重算状态：无差异置 1，仍有差异置 2 并返回 `50204` | AC-3 |

**匹配口径**：支付按 `payment_record.channel_trade_no` 与账单 `tradeNo` 匹配、金额与账单 `amount` 比对；退款按 `refund_request.channel_refund_no` 与账单 `tradeNo` 匹配、金额比对，退款金额恒为正。渠道多收记为正差，渠道少收记为负差。

**只读边界**：对账链路只读取 `payment_record`（`status` 1、3、6 且落在账单日内）与 `refund_request`（`status=2` 且 `refunded_at` 落在账单日内），只写 `payment_reconcile`。任何差异都不得触发订单、支付、退款或权益的写入。
