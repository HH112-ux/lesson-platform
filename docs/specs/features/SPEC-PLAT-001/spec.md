## 2. 背景与目标

后端服务以 `X-User-Id`、`X-User-Roles` 作为唯一身份依据，若客户端可自行携带这些头，越权只需要改一个请求头。本条目冻结网关的信任边界：入站身份头一律剥离，可信值只由网关验签后注入，运营后台路径在网关层完成第一道角色拦截，下游只读头不再信任请求体中的用户标识。

## 3. 范围

### 3.1 包含

- 入站 `X-User-Id`、`X-User-Roles`、`X-User-Source`、`X-Tenant-Id` 等身份头的剥离与规范化。
- JWT 验签、会话吊销校验与身份头注入。
- `/api/v1/admin/**` 路径的 `ADMIN` / `OPS` 角色前置拦截。
- 下游服务只读身份头的信任约定。

### 3.2 范围外

- 登录、Token 签发与 refresh 轮换，见 SPEC-PLAT-003 与认证域。
- 服务间内部令牌 `X-Internal-Token`，见 SPEC-PLAT-005。
- 小程序来源端识别（当前网关只能区分 `admin` 与 `web`），见 SPEC-PLAT-002。
- 服务层的教师归属、订单归属二次校验，见各业务条目。

## 4. 用户场景

| 编号 | 类型 | 场景 | 期望结果 |
|---|---|---|---|
| S-1 | 正常 | 已登录学员携带合法 access token 请求课程详情 | 网关验签后注入 `X-User-Id` 与角色，下游按本人身份处理 |
| S-2 | 异常 | 客户端在请求头中自带 `X-User-Id: 1` | 该头被剥离，下游收到的仍是 Token 对应用户或不存在用户头 |
| S-3 | 异常 | 学员携带合法 token 访问 `/api/v1/admin/users` | 网关返回 `40301`，请求不进入 admin-service |
| S-4 | 异常 | 客户端携带过期或伪造 token 访问受保护接口 | 返回 `40101`（过期返回 `40102`），不注入任何用户头 |
| S-5 | 边界 | 匿名访问公开课程列表 | 不注入用户头，也不因缺少身份头返回 `40101` |

## 5. 验收标准

- AC-1：任何入站请求携带的 `X-User-Id`、`X-User-Roles`、`X-User-Source`、`X-Tenant-Id`，无论大小写、重复次数或是否位于白名单路径，到达下游前均被清除，下游无法读到客户端提供的取值。
- AC-2：未携带 Token、Token 验签失败或会话已被吊销时，访问非公开路径返回 `40101`，且响应不包含任何用户身份信息。
- AC-3：`X-User-Roles` 不含 `ADMIN` 也不含 `OPS` 的请求访问 `/api/v1/admin/**` 时，网关直接返回 `40301`，下游服务收不到该请求。
- AC-4：下游服务处理请求时，用户身份只取自网关注入的 `X-User-Id`，请求体或路径中携带的 `userId`、`teacherId` 不被作为归属判定依据。

## 6. 边界与异常

| 编号 | 触发条件 | 系统表现 | 关联 AC |
|---|---|---|---|
| E-1 | 请求同时携带多种大小写变体的身份头 | 全部剥离，只注入网关生成的一份；记录告警 | AC-1 |
| E-2 | `OPTIONS` 预检与 CORS 请求 | 同样执行剥离，不放行任何客户端身份头 | AC-1 |
| E-3 | access token 过期但 refresh 有效 | 返回 `40102`，由客户端换发，不降级为匿名放行 | AC-2 |
| E-4 | 角色列表超过 20 项 | 网关拒绝并返回 `40001`，不注入超长头 | AC-3 |
| E-5 | 白名单公开路径携带 Token | 不注入用户头；需要用户上下文的公开接口由服务自行处理可选鉴权 | AC-1 |
| E-6 | 内网直连服务端口绕过网关 | 由网络策略与内部令牌二次拦截（见 SPEC-PLAT-005），网关不承担该层 | AC-4 |
