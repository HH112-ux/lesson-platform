# 规格详情模板

> **使用方式**：复制本文件到 `docs/specs/features/SPEC-{DOMAIN}-{NNN}/spec.md`，目录与编号必须与 `docs/specs/{domain}.md` 中的索引行一致。编号只能由索引文件分配，不得在详情文件中新增或跳号；索引表的 AC 摘要必须与本文第 5 节逐条对应，改写语义视为违反已冻结决策。
>
> **语言与标记**：本模板用中文书写，不引入英文占位符体系。未决事项统一写 `[待定]`，每条必须指定 owner 与结案条件；决策落定后删除标记并回填结论。
>
> **AC 写法**：一条 AC 只说一件事，包含「触发条件 + 可观察结果」，可用「是/否」判定。禁止写「能正常下单」「体验流畅」「性能良好」这类无法判定的表述；涉及并发、幂等、权限、金额时必须写明具体判定值与返回码。

## 2. 背景与目标

说明该条目要解决的问题、依据的冻结决策，以及完成后可判定的业务结果。只写决策与目标，不抄现状实现。

## 3. 范围

### 3.1 包含

本条目负责的行为与边界，按「谁在什么入口做什么」描述。

### 3.2 范围外

明确排除的内容，逐条写明由哪个编号承接；无承接条目时写「本期不做」。
