# 规格详情模板

> **使用方式**：复制本文件到 `docs/specs/features/SPEC-{DOMAIN}-{NNN}/spec.md`，目录与编号必须与 `docs/specs/{domain}.md` 中的索引行一致。编号只能由索引文件分配，不得在详情文件中自行新增或跳号。
>
> 本模板用中文书写，不引入英文占位符体系。未决问题统一写 `[待澄清]`，并在条目内说明待澄清点、影响范围与负责人；决策落定后删除标记并回填结论。

## 1. 基本信息

| 项目 | 内容 |
|---|---|
| 编号 | SPEC-{DOMAIN}-{NNN} |
| 标题 | — |
| 来源 | 决策编号或已登记口径（不得引用现状文档或现状实现） |
| 状态 | 未开始 / 进行中 / 已完成 / 已废弃 |
| 计划层级 | L1 / L2 / L3 / 上线后首批 / 真实收款前置 / — |
| 最后核对 | 年-月-日 |
| AC 完成度 | 0/N |

## 2. 背景与目标

说明该条目要解决的问题、对应的决策依据，以及完成后可判定的业务结果。只写已冻结的决策，不抄现状描述。

## 3. 范围

- 包含：本条目负责的行为与边界。
- 不包含：明确排除、由其他条目承接的内容，并写明对应编号。

## 5. 业务规则

逐条列出可执行规则；涉及状态、权限、金额、幂等时必须写明判定条件与失败表现。

## 6. 验收标准

- AC-1：一句话，可用「是/否」判定。
- AC-2：一句话，可用「是/否」判定。
- AC-3：一句话，可用「是/否」判定。

> 验收标准编号在本条目内连续，新增只能追加；AC 完成度按「已通过条数/总条数」回填索引与 `docs/project-status.md`。
