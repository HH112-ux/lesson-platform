# 交易域规格条目

本文件是交易域（下单、优惠券、支付、订单状态、退款、购票、对账）的唯一规格来源。规格条目只依据**已冻结的决策**编写：`engineering-plan.md` 15.2 的 D2/D6/D9/D11、2026-11-09 负责人拍板的五条口径，以及产品文档中已确认的决策；不引用现状实现或存在矛盾的现状描述。

- 编号规则：`SPEC-{DOMAIN}-{NNN}`，三位序号只增不减，废弃条目保留编号并标记「已废弃」，不得复用。
- 状态取值：`未开始` / `进行中` / `已完成` / `已废弃`。
- 计划层级：L1 上线硬门槛、L2 业务闭环、L3 体验与运维、`真实收款前置` 表示未完成不得开启真实收款、`—` 表示无待办。
- 实现状态汇总见 `docs/project-status.md`。

### SPEC-TRADE-001 下单与幂等

**来源**：D2、engineering-plan 2.3、计划 L1-4。
**输入输出**：已登录用户提交课程与客户端幂等键 → 订单与订单明细；重复提交同一幂等键 → 返回首次结果。
**验收标准**：同一用户同一幂等键只产生一笔订单；已持有有效权益时下单返回 61002；课程非已上架状态返回 61001；订单金额由服务端计算，不接受客户端传入价格。
**状态**：已完成｜**最后核对**：2026-11-09｜**层级**：—

### SPEC-TRADE-002 0 元订单

**来源**：D9、2026-11-09 口径「0 元课允许」。
**输入输出**：0 元课程或券后应付为 0 的订单 → 创建即进入已支付并发放权益，不创建支付单。
**验收标准**：`pay_amount=0` 时订单创建后状态为已支付、`pay_expire_at` 为空、权益立即生效；不产生支付记录；重复下单被权益唯一约束与 61002 拦截；原 62008 不再使用。
**状态**：已完成｜**最后核对**：2026-11-09｜**层级**：—

### SPEC-TRADE-003 优惠券校验与核销

**来源**：engineering-plan 2.3/4.3.3、D6（券不退）。
**输入输出**：下单时提交用户券 → 服务端校验归属、有效期、门槛与折扣 → 计算优惠金额并核销。
**验收标准**：券不属于当前用户、已使用、已过期或不满足门槛时返回券不可用业务错误；折扣率缺失或类型不匹配不得返回 500；优惠金额不得超过订单应付金额且应付不得为负；退款成功后券不恢复。
**状态**：已完成｜**最后核对**：2026-11-09｜**层级**：—

### SPEC-TRADE-004 支付发起与重付约束

**来源**：D2（仅 Web 支付宝）、D11（重付先关原支付单）、engineering-plan 2.3。
**输入输出**：用户对已支付截止前的待支付订单发起支付 → 支付单；小程序来源请求下单 → 拒绝。
**验收标准**：渠道由来源端固定为支付宝，客户端不能自选；小程序下单返回 62011；同一订单存在未关闭支付单时重新发起返回 62006，关闭后方可重发；非待支付订单发起支付被拒。
**状态**：进行中｜**最后核对**：2026-11-09｜**层级**：L1-3、L2-2

### SPEC-TRADE-005 支付回调与三态处理

**来源**：D2、engineering-plan 2.3、已登记的回调处理约定。
**输入输出**：支付宝异步通知 → 验签、金额核对、订单与支付单状态更新、权益发放意图写入 outbox。
**验收标准**：验签失败或金额不一致拒单并告警；重复通知幂等返回成功；订单已支付时按幂等成功返回；订单已关闭或已失效时落库留痕并指向退款补偿，不得静默丢弃；订单不存在时拒绝。
**状态**：已完成｜**最后核对**：2026-11-09｜**层级**：—

### SPEC-TRADE-006 订单取消

**来源**：engineering-plan 2.3。
**输入输出**：用户取消本人待支付订单 → 订单已取消并关闭对应支付单。
**验收标准**：仅待支付订单可取消；取消后原支付单状态为已关闭；非本人订单返回 40301；重复取消幂等返回成功。
**状态**：已完成｜**最后核对**：2026-11-09｜**层级**：—

### SPEC-TRADE-007 超时关单

**来源**：D11（30 分钟）。
**输入输出**：创建超过 30 分钟仍未支付的订单 → 自动进入已关闭并关闭支付单。
**验收标准**：无需用户操作，超时订单在约定调度周期内变为已关闭；并发关单不产生重复状态或异常；已支付订单不被误关。
**状态**：未开始｜**最后核对**：2026-11-09｜**层级**：L1-3

### SPEC-TRADE-008 退款准入

**来源**：D6、2026-11-09 口径「按 D6 严格执行」。
**输入输出**：学员对本人已支付订单申请退款 → 合规时生成待审核退款单，不合规时直接拒绝。
**验收标准**：付款后 7 天内且学习进度不超过 20% 才生成退款单；超期或进度超限返回 62007 且不生成退款单、不转人工；退款金额必须等于实付金额；学习进度查询不可用时失败关闭（50201），不得按 0 处理。
**状态**：已完成｜**最后核对**：2026-11-09｜**层级**：—

### SPEC-TRADE-009 退款审核与状态机

**来源**：D6、engineering-plan 2.3、审查结论 A6。
**输入输出**：运营审核待审核退款单 → 通过（0→1→2/4）或驳回（0→3），并联动订单状态。
**验收标准**：退款单状态仅允许 0 待审核、1 调渠道中、2 已退款、3 驳回、4 失败；审核通过先落状态 1，再调用渠道，渠道成功置 2 并将订单置已退款；驳回必须填写不超过 300 字原因、订单回到已支付；非待审核状态重复审核不产生二次退款；同一订单同时只允许一条进行中退款单。
**状态**：进行中｜**最后核对**：2026-11-09｜**层级**：L1-1

### SPEC-TRADE-010 退款失败与补偿

**来源**：engineering-plan 2.3（退款失败回已支付）、审查结论 C2/C3、计划 L1-1。
**输入输出**：渠道退款失败或调用异常 → 退款单置 4 并记录失败原因，订单回到已支付，允许重新申请。
**验收标准**：任何渠道异常（含超时、网络错误）都落失败状态并留下可查询原因，不得回滚成无记录；失败后同一订单可重新申请且仍受 D6 准入约束；并发重复申请稳定返回同一进行中退款单而非 500。
**状态**：进行中｜**最后核对**：2026-11-09｜**层级**：L1-1

### SPEC-TRADE-011 退款成功后的权益处理

**来源**：D6、engineering-plan 2.3。
**输入输出**：退款成功后撤销权益 → 权益软失效，学习记录保留，课程按未购处理。
**验收标准**：退款成功后权益状态失效但记录不物理删除；该用户再次访问课程按未购处理；学习进度记录保留；同一退款重复回调不重复撤销。
**状态**：已完成｜**最后核对**：2026-11-09｜**层级**：—

### SPEC-TRADE-012 购票（Web 购买、小程序引导）

**来源**：D2（ticket 流程）、`docs/purchase-flow.md`、计划 L2-2。
**输入输出**：Web 端登录用户生成购票凭证与兑换入口；小程序签发凭证并在 Web 兑换后登录或进入课程。
**验收标准**：凭证一次性使用且有时效；兑换成功后跳转目标课程；过期或重复兑换返回明确错误；小程序不直接创建订单或发起支付。
**状态**：进行中｜**最后核对**：2026-11-09｜**层级**：L2-2

### SPEC-TRADE-013 金额单位与边界约束

**来源**：审查结论 A11/C1/C5、计划 L1-2。
**输入输出**：所有交易金额写入数据库与对外接口展示 → 单位与精度统一，并在数据库层兜底。
**验收标准**：数据库金额字段对非负性有约束；对外接口金额统一以分表示，页面展示前完成换算；价格与优惠金额超过两位小数时被拒绝而非静默舍入；订单、支付、退款三处金额均可相互校验一致。
**状态**：进行中｜**最后核对**：2026-11-09｜**层级**：L1-2

### SPEC-TRADE-014 支付对账与差异处置

**来源**：D2、engineering-plan 5.2/附录 A、审查结论 A13、计划「真实收款前置」。
**输入输出**：每日导入支付宝账单 → 与支付单比对，生成差异记录并支持人工处置。
**验收标准**：T+1 账单可导入且重复导入不产生重复差异；金额或笔数不一致生成差异单并告警；差异未处置时阻断日结；**未完成对账能力不得开启真实收款**。
**状态**：未开始｜**最后核对**：2026-11-09｜**层级**：真实收款前置
